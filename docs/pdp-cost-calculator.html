Economics

Gas optimization (SP levers)

Throughput cost of gating: gated registration only lands while base fee ≤ gate, so achievable rate = capacity × duty. If that can't keep up with arrival, onboarding extends and the delayed data forgoes revenue (≈ ½ × extension × revenue rate) — a penalty that grows with piece count, so small pieces pay it most. Capacity ~1 tx/30s-block ≈ 120/hr per sender; raise it to model parallel sender addresses.
Verified against Piri + contracts: Piri gates deferrable txns (addPieces, deletes) with a per-message max-fee cap (defer-and-retry, no penalty) → modeled as paying registration at min(prevailing, gate)+premium. Proving must land in its challenge window, so it pays the prevailing fee; missing a period has no slashing — you simply forgo that period's pay. Set "% proven" <100 to model skipping spike days: revenue and proving cost both scale by it (registration/churn do not). Premium reflects Piri's GasFeeCap = baseFee + SuggestGasTipCap.

Workload

Churn / deletion (where piece size really bites)

If object < piece, each churn event repacks a whole aggregate: on-chain gDel+gAdd (size-independent!) plus off-chain re-hash of the aggregate. Under pure delete, a standalone piece (piece ≤ object) costs only gDel — no survivor re-add. That, plus the off-chain re-hash, is the real case for small pieces. Off-chain $/TiB is backend-dependent (local disk ~$0.1–1; S3 egress ~$90).

Cost vs piece size (log-log · ★ optimum · dashed = object size · horizon $)

Everything is a function of piece count N = dataset ÷ piece size. On log-log axes the power-laws are straight lines: registration ∝ 1/P (down), off-chain repack ∝ P (up); their sum is the valley whose floor is the optimum.

Revenue / cost over time (the onboarding ramp · dashed = data fully online)

Revenue accrues on the growing registered base: it ramps up during onboarding (slow throughput lengthens the ramp and lowers total revenue), then runs flat once data is fully online. Where the Profit line crosses 0 is break-even.
